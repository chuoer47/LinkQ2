## 1. 代码边界原则（先于目录结构，这是更重要的决定）

**凡是项目叙事里"这是我的东西"的部分必须手写；凡是叙事里不需要的部分，用现成的，省下的时间全部投给核心。**

### 1.1 引擎形态：划法 B（已拍板）

> A 是"给 transformers 写三个插件"（否）；
> **B 是"拿 transformers 当算子库，引擎是自己的"（采用）**；
> C 是"连算子库都是自己的"（工作量否决）。

具体分工：

**手写（核心，项目身份所在）**：

| 部件 | 位置 | 说明 |
|---|---|---|
| W4A16 GEMM kernel | `kernels/csrc/w4a16_gemm.cu` | M1 灵魂，反量化+FP16 MMA 融合 |
| KV4 attention kernel | `kernels/csrc/kv4_attention.cu` | M2 灵魂，kernel 内反量化 |
| KV cache 管理 + 量化数据路径 | `qslab/cache/kv_cache.py` | fp16/kv8/kv4 三实现，KV4 算法载体 |
| 量化器 | `quantizer/` | W4 group-wise + KV4 plan + **自有打包格式**（"自己的系统"最硬证据） |
| 投机采样数学 | `qslab/sampler.py` + `qslab/spec/` | 拒绝采样 / accept-reject / 回滚，算法层必须自己写 |
| **decode 主循环** | `qslab/engine.py` | 自己编排 draft/target 交替（transformers 的 assisted decoding 只当正确性 oracle） |
| Qwen3Attention 替换子类 | `qslab/model/patched.py` | 干净替换调用点（见 1.2） |

**用现成（非核心）**：

| 部件 | 用什么 |
|---|---|
| Qwen3 模型定义（前向各模块） | transformers `Qwen3ForCausalLM` |
| tokenizer | transformers tokenizers |
| safetensors 权重读取 | safetensors 库 |
| RoPE / RMSNorm / SwiGLU / QK-Norm 算子 | transformers 自带实现 |

### 1.2 kernel 替换机制（已拍板）

不 monkey-patch（脏）。写自己的 `Qwen3Attention` / `Qwen3MLP` 子类（~100 行），替换 transformers 模型里的对应模块：
- attention 的 `torch.matmul` 调用点 → `qslab_kernels.w4a16_gemm`
- KV cache 读写 → `qslab/cache/kv_cache.py` 的三实现
- 好处：调用点显式、可控、调试清晰；transformers 保留为调试对照 oracle

### 1.3 依赖纪律

- `qslab/` + `kernels/` + `quantizer/` **禁止 import transformers**（kernels 连 torch 都只在绑定层出现）
- `adapters/` 是唯一允许 import transformers/vllm 的地方
- transformers 的用途只有三个：模型定义来源、调试 oracle、tokenizer

├── adapters/                      # 薄粘合层（唯一允许 import transformers/vllm 的地方）
│   ├── tokenizer.py               # HF tokenizers 封装成引擎接口
│   ├── download.py                # ModelScope 下载 Qwen3-8B/0.6B
│   └── baseline_vllm.py           # 对照组：同模型 FP16/AWQ-Marlin 吞吐

│   ├── bench_throughput.py        # tokens/s（batch=1 decode，主指标）
│   ├── bench_ppl.py               # WikiText2/C4 PPL

├── tests/                         # 纯逻辑单测（不占 GPU）

## 3. 工作流约定（已拍板部分）

- **git**：服务器为 git 主战场，`PROGRESS.md` 唯一状态源，commit 格式 `[M1-xxx] 摘要`，models/ gitignore，暂不推远端
- **同步**：本地 `F:\code_lib\claude-workspace\qserve-lab\` 作为 docs/notes 编辑镜像，通过 **MCP SSH Manager**（`ssh_upload`/`ssh_download`/`ssh_execute`）操作服务器，服务器名 `4090_public`
- **设计文档层**：每个 M 动工前先写半页 `docs/design-<topic>.md`（数据流 + 格式定义 + 验收标准），写完再动手
- **env 铁律**：所有 pip/conda 操作只在新项目 env 内进行（env 名待 setup 时定），不污染其他 env
