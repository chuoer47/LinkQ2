## 0. 量化器的全貌

```
输入：HF checkpoint（Qwen3-8B BF16, ~16G safetensors）
输出：自有打包格式 qslab_w4_v1（~5G），能被 engine 的 loader 直接加载
```

四步数据流：**校准 → 量化算法 → 打包格式 → 与引擎交接**。

## 1. 校准（calibrate.py）

- 数据：冻结校准集 `results/frozen/calib_c4_128x2048.pt`（协议已冻结）
- 流程：FP16 模型前向（纯统计，不训不更新）→ per-layer Linear 输入激活统计量
- **设计原则：校准器与算法解耦**——calibrate.py 只管"采"（统一的 per-layer 激活统计钩子），w4.py 只管"算"
- v1 统计量：`absmean`（per-channel 激活绝对值均值，AWQ scaling 所需）+ `absmax`
- 接口留位：M1 若引入 GPTQ 式误差反传，钩子结构已预留（不实现）

## 2. 量化算法（w4.py）

两层结构，`--algo rtn|awq` 开关（**AWQ scaling 已拍板引入**）：

| 层 | 算法 | 地位 |
|---|---|---|
| 第一层 | **RTN group-wise**（group=128，每组 scale，四舍五入 4bit） | M1 地基，检验整条链路的正确性基准；PPL 预期劣化 0.1~0.3 |
| 第二层 | **AWQ scaling**（激活感知等价变换 `W'=W·diag(s)`, `x'=x/diag(s)`，逐层 grid search s∈[0,1] 步长 0.05 选 MSE 最小） | ~+150 行；RTN 压不过验收线 0.3 时的保险；与 LinkQuant 03 篇呼应 |

- **明确不做**：GPTQ（二阶误差反传，工程量大，留作"未来工作"一行字）、OmniQuant 等可学习量化（超范围）
- M1 笔记章节：RTN vs AWQ scaling 的 PPL 对比（自有实验数据）

## 3. 打包格式（packfmt.py）—— qslab_w4_v1

```
qslab_w4_v1/
├── config.json          # 模型架构 + 量化配置 + format_version + kv4_plan 字段（预留）
├── tensors.safetensors  # 打包后的权重
└── calib.json           # 校准集指纹（hash），保证可追溯
```

权重 tensor 物理布局（直接服务 kernel）：

```
qfp:  [out_features, in_features/8]   uint32   # 8 个 4bit 打包进 1 个 uint32
scale:[out_features, in_features/128] fp16     # group-wise scale
zero: [out_features, in_features/128] fp16     # 对称量化时恒 0
```

**已拍板的三个渐进策略**：

1. **对称先行、非对称留字段**：v1 的 zero 恒 0（对称），kernel 跑通后若 PPL 有差距再启用真值非对称——格式不变，前后兼容
2. **v1 不做权重 shuffle**（不按 tensor core 访问模式预重排）：kernel 内做位提取（第一版能跑）；若 1.3× 验收线不够，引入 v2 格式 + 预 shuffle，靠 `format_version` 迁移
3. **格式冻结点 = 链路跑通**，不是"性能达标"——格式冻结太早是量化系统常见死法，性能优化是 v2 的事

## 4. KV4 plan 接口（kv4_plan.py，M2 实现，schema 现在预留）

- 离线部分：校准集前向测每层 KV 离群程度（absmax 分布），离群严重的层保 FP16
- 输出写进 config.json：

```json
{"kv_fp16_layers": [0, 1], "k_quant": "per_channel", "v_quant": "per_token"}
```

- engine 加载时按 plan 初始化各层 cache 实现（fp16 / kv8 / kv4 三选一）
