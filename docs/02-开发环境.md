## 1. 约束盘点（2026-09-14 实测/核实）

| 约束 | 事实 | 影响 |
|---|---|---|
| Qwen3 支持 | transformers **≥4.51.0** 才有 `Qwen3ForCausalLM` | transformers 下限 4.51 |
| Cache/attention 重构 | **transformers 5.x 是破坏性大版本**（Cache API 全改、attention 模块重构、`AttentionInterface` 注册制），`patched.py` 替换子类方案最怕这个 | **pin 在 4.x**，取 4.57.6 |
| nvcc 兼容规则 | nvcc 必须 **≥** torch 编译的 CUDA 版本；12.x 内 minor 兼容（torch≥2.4） | nvcc 12.4 配 cu121/cu124 ✅；配 cu126+ ❌（官方未支持，flash-attn 有 segfault 前科） |
| gcc | nvcc 12.4 最高支持 gcc 13（服务器系统 gcc 14 不可用） | 复用 leetcuda 的 conda-forge gcc-13 `-ccbin` 方案 |
| 服务器现状 | leetcuda: torch 2.5.1+cu124 + nvcc 12.4 ✅；linkquant: torch 2.7.1+**cu126**（nvcc 不匹配 ❌）；vllm: torch 2.8.0+cu128 | 无现成 env 可用，必须新建 |

## 2. torch 版本权衡（记录决策理由）

- **方案甲（采用）：torch 2.5.1+cu124** —— nvcc 12.4 精确匹配，kernel 编译零风险，gcc-13 工具链现成（leetcuda 已验证）
- 方案乙（否决）：torch 2.7.1+cu126 + 重搭 nvcc 12.6 工具链 —— 要把 leetcuda 踩过的 8 个坑（include 路径/软链/stub .a）重来一遍，收益为零（我们不用 torch 2.6+ 的任何新特性）
- **决策依据**：kernel 编译是 M1/M2 的命脉，已验证的工具链是最大资产
- vLLM 基线在 `vllm` env（torch 2.8.0+cu128, vllm 0.11.0）跑，env 隔离，互不干扰

## 4. 环境搭建步骤（scripts/setup_env.sh 的内容依据）

```bash
source <conda-base>/etc/profile.d/conda.sh
conda create -n qslab python=3.11 -y
conda activate qslab

# torch 生态（清华源）
pip install torch==2.5.1 numpy'<2.1' transformers==4.57.6 accelerate safetensors

# CUDA 编译工具链（官方 nvidia channel + conda-forge，清华 nvidia 镜像 404 勿用）
conda install -c nvidia cuda-nvcc=12.4 -y
conda install -c conda-forge gcc_linux-64=13 gxx_linux-64=13 -y

# 验证
which nvcc && nvcc --version        # 12.4
python -c "import torch; print(torch.__version__, torch.version.cuda)"  # 2.5.1 12.4
```

kernel 编译时（`scripts/build_kernels.sh`）：
```bash
export CUDA_HOME=$CONDA_PREFIX
export TORCH_CUDA_ARCH_LIST="8.9"    # 4090 = Ada = sm_89
# nvcc 参数加 -ccbin $CONDA_PREFIX/bin/x86_64-conda-linux-gnu-g++
```

## 5. 遗留经验提醒（来自 leetcuda，编译遇坑先查这里）

1. pip 的 `nvidia-cuda-nvcc-cu12` wheel 只带 ptxas 不带 nvcc → 必须 conda 装 `cuda-nvcc=12.4`
2. conda/pip 都不提供 `libcudadevrt.a`/`libcudart_static.a` → 空 stub + `--cudart shared` + rpath 内嵌（若 kernel 需要动态并行才用）
3. pip wheel 的 include 分散在 `site-packages/nvidia/<组件>/include`，缺头文件按组件补 include 路径
4. `nv/target` 头在 `nvidia-cuda-cccl-cu12`（单独装）
5. pip wheel 只有 `libxxx.so.12` 无主链接符 → 建 `.so -> .so.12` 软链

> 注：qslab 的 kernel 只依赖 torch extension 基础设施（cuda_runtime + cublas 可选），大概率用不到上面 2/3/4/5 条，但编译报错时按此排查。
