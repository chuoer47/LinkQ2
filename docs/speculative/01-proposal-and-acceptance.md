# 投机算法：候选、验证与接受

投机推理让较便宜的方法先提出多个候选，再由目标模型一次验证，减少每交付一个 token 所需的目标模型调用。目标模型仍决定最终交付；候选本身不能直接写成确定输出。

本篇描述项目现有算法，纯 token 提议与接受位于 `qslab/speculation`，模型、KV、Graph 适配位于 `runtime/speculation`。两层之间通过候选 token 和可选概率传递信息。

## 1. 为什么验证 k 个候选需要 k+1 行

设已提交历史为 $x_{1:L}$、候选为 $d_1,\ldots,d_k$。目标输入从最后一个已提交 token 开始，包含：

$$
[x_L,d_1,\ldots,d_k].
$$

目标对这 $k+1$ 个位置产生下一 token 分布：前 $k$ 行验证各候选，最后一行用于全部接受后的 bonus。每行具有不同的因果可读范围，不能通过一次无因果约束的批计算替代。

候选为空时回普通 decode；窗口会被预算、上下文和输出余额裁短。名义窗口不等于每轮实际候选数。

## 2. Greedy：只接受连续匹配前缀

当 temperature 不大于 $10^{-6}$，使用目标 argmax。设目标给出的验证 token 为 $v_1,\ldots,v_{k+1}$，接受长度为：

$$
A=\max\{a\in[0,k]:d_i=v_i\ \text{for all }1\le i\le a\}.
$$

最终提交 $d_1,\ldots,d_A,v_{A+1}$。第一次不匹配后即停止接受，不能跳过错误候选继续接受后面的匹配；全部接受时则多提交一个 bonus。

例如候选 `[10,20,30]`、验证 `[10,99,30,40]`，只交付 `[10,99]`，不是 `[10,99,30]`。停止条件可能再截短到 EOS 或剩余输出预算。

实现：[accepted_prefix](../../qslab/speculation/acceptance.py)。它只返回 token 和接受数量，不直接修改 Sequence 或 KV。

## 3. 随机采样：概率比接受与残差分布

记目标分布为 $q$、实际用于生成候选的草稿分布为 $p$。候选 $d$ 的接受概率为：

$$
\alpha(d)=\min\left(1,\frac{q(d)}{p(d)}\right).
$$

拒绝时，从以下归一化残差重新采样：

$$
r(v)=\frac{\max(q(v)-p(v),0)}{\sum_u\max(q(u)-p(u),0)}.
$$

项目自回归草稿返回采样时实际使用的温度分布，避免“拿一种分布生成、用另一种分布接受”。n-gram 等确定性提议按 one-hot 草稿分布处理：接受概率为目标对候选的概率，拒绝后的残差排除该候选。

接受/拒绝产生验证 token 后，仍只取连续接受前缀与一个纠正/bonus。随机条件下的分布正确性不要求与普通采样在相同 seed 下逐 token 相同；也不能用 greedy 的 argmax 匹配规则代替概率比规则。

上述分布结论依赖正确的条件概率和因果执行。有限精度、不同 query 形状及缓存路径仍需额外验证，算法公式本身不能证明整个量化系统严格无损。

## 4. 四种 proposer

| 方法 | 候选从哪里来 | 状态与成本 |
|---|---|---|
| ngram | 用历史末尾 n-gram 匹配最近的较早出现位置，取后续 token | CPU 查找，无模型权重 |
| lookahead | 每请求维护历史 n-gram 索引，并沿索引扩展候选 | CPU 索引，结束时清理 |
| draft | 小型自回归模型逐 token 生成 | 额外模型、KV、补算和多次 forward |
| dflash | 目标特征条件化的官方块草稿模型 | 额外 BF16 模型、特征缓存、专用 Graph |

这里的 LookaheadProposer 是项目内的索引与链式扩展实现，不应仅因名称相同便等同于其他论文中的完整算法。n-gram 和 lookahead 的索引不应跨请求共享候选来源，否则输出会依赖其他请求文本。

当前 DFlash 只支持 greedy；随机接受的通用实现不表示 DFlash 已支持随机生成。模型与配置组合见[接入文档](02-models-and-state.md)。
