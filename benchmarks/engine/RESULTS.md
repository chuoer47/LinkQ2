# 引擎第一版实测记录

日期：2026-10-16。设备：RTX 4090 D，GPU 1；项目 `.conda`，torch 2.7.1+cu126、FlashAttention 2.8.3。模型为 Qwen3-8B，W4 使用现有 RTN 完整 checkpoint；KV4 使用现有校准文件，没有重新量化或校准。

原始结果：`results/engine/2026-10-16-v1-final/`。FP16 KV 两组测于 `03708fb`，KV4 两组测于页大小绑定修复后的 `0a3e5aa`；`run.json` 逐组记录提交。后续 `8b9ae31` 仅补充 close 内的 Python 引用环回收与 HTTP 最后一个上下文位置的准入，单独验证，没有重复不受影响的性能测量。

## 结论

- 第一版单请求 eager 主链路完成：FP16/W4 权重与 FP16/KV4 缓存可以独立选择；W4 实际替换 252 个投影。FP16 KV 使用官方 FlashAttention 分页接口。
- 权重存储从 15.256 GiB 降到 5.654 GiB；固定 1024 token KV 池从 144 MiB 降到 37.195 MiB，压缩约 3.87 倍。W4 加载使用 meta 参数，启动峰值约 5.975 GiB。
- 当前没有端到端加速。512 输入时，FP16 TPOT 为 29.053 ms；KV4 为 35.599 ms；W4 为 74.560 ms；W4+KV4 为 81.570 ms。这里只建立普通 eager 基线，后续需要定位开销再优化。
- 固定参考历史的 48 个位置中，FP16 KV 的原始权重/HF FP16 top1 一致率为 97.92%，W4/HF fake 为 100%。KV4 两组分别为 81.25% 和 93.75%；详细误差见下表。数据很小，不能作为 PPL 或通用精度结论。
- 完成、等待取消、运行取消、上下文截断均归还全部页面；关闭后回到 cuBLAS 工作区基线 8.125 MiB，无存活模型 CUDA Tensor。独立诊断清理库工作区后 allocated 归零。
- 主回归 42 项通过；close 直接释放和 HTTP 边界补测 11 项通过。日志在服务器仓库外 `../linkq2-engine-20261016/page-fix-tests.log`、`close-fix-tests.log`。
- 本次未修改 GemLite 或 KV4 算子的计算实现。KV4 的 256 token 页面大小已与调度器、物理池同步，回归测试覆盖非零物理页与两种页大小。

本轮验收范围是单请求 eager。并发调度公平性、压力抢占、CUDA graph 和投机推理留待后续阶段。
