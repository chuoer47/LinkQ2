## 引擎实现要点（踩坑实录）

1. **transformers 4.57 的 attention 属性在 config 上**：`num_attention_heads`/`num_key_value_heads` 不再是 module 属性，替换子类要从 `config` 取。
2. **替换子类必须绕过父类 `__init__`**：直接 `torch.nn.Module.__init__(self)` 然后逐个"偷"父类的投影模块（q/k/v/o_proj、q/k_norm），避免重新分配 4GB 权重。权重零拷贝，替换只换行为。
3. **RoPE 位置修复（关键 bug）**：decode 单步只喂 1 个 token 时，backbone 默认 `cache_position=0`，cos/sin 按位置 0 算 → 输出从头就分叉。修复：`decode_step` 显式传 `cache_position=start_pos`。**症状是 prefill 后第一个 decode token 就错，排查方向是先对 prefill logits（本例 prefill diff=0.0，问题必在 decode 侧）。**
4. **engine 复用要 reset cache**：连续 generate 时 KV cache 残留上一轮数据 → causal mask 尺寸错乱。`generate()` 入口统一 `reset_cache()`。
5. **HF 网络约束**：服务器 huggingface.co 直连不可达，datasets 下载会无限重试。解法：`HF_ENDPOINT=https://hf-mirror.com`，数据集已进 arrow 缓存后可离线加载。
6. **Qwen3-1.7B 结构**：28 层、16 Q / 8 KV heads、head_dim 128、GQA group=2——KV4 的 per-channel 分组粒度天然整齐。

## 对后续里程碑的意义

- decode 单步 23.5ms 里，attention 的 KV 读取和 GEMM 都是朴素 PyTorch——M1 的 W4A16 kernel、M2 的 KV4 attention 就是在这个 baseline 上扣时间
- oracle 对齐链路已经建立：以后任何 kernel 改动都可以用"token 级一致 + prefill logits diff"快速验证正确性
- benchmark 脚本（gpu 快照/多轮中位数/json 落盘）已成模板，M1 起直接复用

## 遗留

- PPL 目前 16 docs（跑全套 435 docs 时间较长），M1 前把 docs 数提到与协议一致的量级并冻结
- throughput 的 round 4 有 48.8 的离群高值（GPU 波动），median 已经稳
