# notes/M9 — n-gram 投机解码接入 runtime

日期：2026-09-18。方案与业界依据：docs/design-m9.md。

## 一、做了什么

**n-gram 投机解码真实接入 M8 引擎**（W4A16 + KV4 + paged + CUDA Graph 全链），
`LLMEngine(spec_method="ngram", spec_num_drafts=γ)`：

- **L0**：`kv4_paged_decode_kernel` 加 `M: constexpr`——grid `(N_Q, bs*M)`，
  row = seq*M + m，读取上界 = L+m。因果性=槽位下界（draft KV 在更高槽，
  天然被各行 mask 排除，不需要显式 mask）。M=1 逐指令等价于原 decode kernel
- **L3**：`qslab/runtime/ngram.py`——numpy 滑窗取末 n 个 token 最后一次出现的后继，
  纯 CPU（vLLM V1 同款）
- **L4**：调度器 verify 分支（propose + 预留 γ 槽位）→ runner `run_verify`
  （M=γ+1 行一次前向，(bs, M) graph 族）→ scheduler `postprocess_verify`
  （greedy 接受 + 提交 + trim 回规范块表）
- **回收走 TGI append-only 路线**（不做 vLLM V0 的 page-table 回滚）：
  被拒槽位随尾部块还回 free list，池内垃圾无人读
- **padding 中立**：无提案的序列 pad 到 γ——接受循环钳制在真实提案数 k 内，
  dummy 永不被接受，该步严格等价普通 decode（温度>1e-3 的序列因此不受影响）
- 混合批（spec/非 spec、greedy/温度）全部安全；跨块、max_model_len 截断、
  eos mid-draft、提案中途预算截断均有路径

## 二、结果（graph，greedy，γ=4；复读=copy-prompt）

| 模型 | 文本 | 基线 | 投机 | 加速 | 接受 |
|---|---|---|---|---|---|
| 1.7B fp16KV | 复读 | 145.5 | 455.9 tok/s | **3.13×** | 3.54 tok/步 |
| 1.7B | 自然 | 145.5 | 212.3 | 1.46× | 1.62 |
| 1.7B | 随机 | 140.6 | 180.8 | 1.29× | 1.44 |
| 8B W4A16KV4 | 复读 | 97.2 | **310.4 tok/s** | **3.19×** | 3.54 |
| 8B | 自然 | 98.0 | 93.2 | 0.95× | 1.05 |
| 8B | 随机 | 95.0 | 89.5 | 0.94× | 1.05 |

- γ=8 复读：1.7B **5.77×**（843 tok/s，6.82 tok/步）
- 诚实口径：8B 自然/随机文本有 ~5% verify 开销（vLLM ngram 同样报告此类开销）
- 复读文本上 spec 输出与非投机 **128/128 token 完全一致**（greedy 数学等价兑现）

## 三、Marlin crossover 修正（M5 结论被 e2e 推翻）

排查 8B 投机首测 0.28× 时发现：`w4.auto` 的 M5 微基准 crossover（v1 赢 M<8）
**在 e2e 上不成立**：

| 测量 | v1 | Marlin | 结论 |
|---|---|---|---|
| M=1 decode 1.7B | 145.0 | 155.2 tok/s | Marlin 赢 1.07× |
| M=1 decode 8B | 54.1 | **91.1 tok/s** | Marlin 赢 1.69× |
| M=5 verify 8B | 65 ms/步 | 11.5 ms/步 | v1 逐行重读权重，Marlin 只读一遍 |

- **M8 遗留"8B decode 55.8 tok/s 未查因"的答案就是 v1 GEMV**；切 Marlin 后
  主线 8B W4A16KV4 decode = **97.2 tok/s（1.75×）**
- 数值无损：Marlin vs v1 logits 相互偏差 **0.047**（两者对 fp16 都是 ~4.0，
  即 W4 量化本身）；PPL 不变，口径不动
- `CROSSOVER_M=8→0`，且 Marlin 可用时**不再构建 v1 权重副本**（原先 auto
  两份 packed 布局同时驻留显存，v1 是死重）
- 微基准教训（与 M8 的 cuBLAS tiling 教训同族）：**单算子固定开销模型
  不能外推到图内 252 层前向**——验收要看 e2e
- 代价：`test_w4_runtime` 的 16-token 逐 token ORACLE 在第 12 位翻转
  （W4 logits 本来就离 fp16 ~4.0，近并列必翻）→ 断言改稳定前 12 token 前缀，
  与 M8 已确立的混沌口径一致

## 四、测试

新增 21 个：kernel 7（对拍/因果性/-1 防护）+ proposer 7 + 引擎 7
（padding 中立、replay-stub 接受率、步数减少、确定性、跨块、短 prompt、graph）
+ 8B spec 1。全量回归绿（非 e2e 31 + e2e 21 + 8B 2）。
断言口径：**不断言 spec 与非投机输出逐 token 相等**（两路径 GEMM M 维不同
→ tiling 漂移，M8 已定性），断言数学结构（接受机制、步数、确定性）。
