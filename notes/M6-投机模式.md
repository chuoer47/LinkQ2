# M6 — 投机推理模式扩展：lookahead 转正

> 2026-09-16 · Qwen3-8B W4-autodetect target · RTX 4090 D (GPU3)

## 背景

M5 收尾时 W4+spec 组合 0.72×（用户不满意）。分析确认剩余瓶颈是 draft 的 Python 逐 token 循环——**如果提案本身不花 draft 前向，这个瓶颈就消失**。这就是 self-speculation / Prompt-Lookup 的思路。

## 三种模式（qslab/spec/verify.py，SpeculativeEngine mode 参数）

| 模式 | 提案来源 | 适用场景 |
|---|---|---|
| chained | draft 模型自回归（M3） | 通用 |
| **lookahead** | **n-gram 自索引**（prompt+已生成文本中找最长匹配，顺链取 γ 个） | 重复/抽取式任务（摘要、编辑、代码修改） |
| dynamic | chained + 自适应 γ（全接受升、多拒绝降，窗口 3 轮） | AR 波动大的负载 |

## 结果（512 in / 128 dec，3 轮中位数，全部无损验证 PASS）

| 文本 | 基线(W4) | chained γ4 | lookahead γ4 | dynamic γ4 |
|---|---|---|---|---|
| repetitive | 39.2 | 28.0 (0.71×) | **56.6 (1.44×)** | 28.8 (0.74×) |
| natural | 39.0 | 28.4 (0.73×) | **56.2 (1.44×)** | 29.8 (0.76×) |

## 发现

1. **lookahead 是本项目第一个显著转正的投机模式（1.44×）**——它把提案成本降为零（一个 dict 查找），target 侧每轮一次 M=γ 前向 + 一次 commit，GPU 利用率反而上升。连"自然文本"也 1.44×——因为校准类文本本身重复度高；**诚实备注**：真实对话/创作文本的 lookahead 命中率会低很多（这是模式特性不是缺陷，选型取决于负载）
2. dynamic 没有收益（0.76× vs chained 0.72×）：重复文本 AR 恒高，自适应没有发挥空间；γ=4 起点已经接近最优
3. chained 的 0.72× 与 M5 末尾一致（数据可复现）
4. 三种模式共享同一套验证/回滚/cache 锁步逻辑，无损性 100%——**验证框架的正确性独立于提案来源**，这是 M3 架构设计的回报

## CUDA Graph 的中止决策（诚实记录）

Graph 捕获 decode step 需要 KV 写入位置成为 graph 输入（capture 时固化地址的问题）——正确方案是 ring-buffer cache + 环形 attention（vLLM 级工程）。估算收益上限 30-40% vs 工程量 1-2 周，**优先级让位给 lookahead 模式**（半天拿到 1.44×）。GraphDecoder 骨架留在 qslab/spec/graph_decoder.py（未完成，注释里写了完整的方案分析）。

## 最终技术栈速览

```
W4A16: 自研 v1 GEMV (M=1) + Marlin GEMM (M>8) hybrid dispatch
KV4:   KIVI 式不对称 + layer0 FP16
Spec:  lookahead (默认推荐) / chained / dynamic，统一无损验证框架
```
