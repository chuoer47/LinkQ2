> 2026-09-16 · Qwen3-8B (target) + Qwen3-0.6B (draft) · RTX 4090 D (GPU3)

## 关键发现

1. **M1/M2 的 8B 复测预言全部兑现**：
   - W4 PPL 劣化 +1.24 与 1.7B **完全一致**（AWQ 配方可迁移）
   - KV4 显存省 **3.5× 达标**（1.7B 时 3.34× 未达——8B 层数多摊薄固定成本，M2 预言正确）
   - KV4 的 PPL 增量 +0.39（1.7B 时 +0.56）——更小模型的校准统计天然吃亏
2. **投机推理在 8B 转正**：0.74× → 1.19×（10.8/9.0）。M3 的分析（dispatch 占比随 target 增大而摊薄）定量验证。未到 1.5× 线，剩余瓶颈：draft 是 Python 逐 token 循环（0.6B 5 次 forward ~5ms CPU dispatch）+ 未用 CUDA Graph。
3. **W4 tok/s 反常慢于 fp16（14 vs 42）**：8B 的 fp16 走 cuBLAS 高度优化的 GEMV；我们的 w4a16 kernel 在 8B 大形状（4096×12288 类）只有 1.14×（M1b 已知短板），叠加 W4Linear 从 pack 读取的带宽开销。**诚实结论：当前 kernel 版本在 8B 上 kernel 级收益 < cuBLAS 基线优势**。kernel 优化（寄存器重排 + mma 管线，即 Marlin 方向）是明确的后续工作。
4. **32K NIAH 补考通过**：fp16 100% / kv4 100%（降幅 0%）——M2 的遗留项关闭，KV4 在 8B+32K 完全无损。1.7B 检索上限 1K-2K vs 8B 轻松 32K——模型能力的天堑实证。

## 工程发现

- **8B 双权重共存 OOM**：fp16(16G) + pack(3.5G) > 22G。两处修复：
  a) `swap_w4_linears` 流式化——先 `mod.weight=None` 释放再装 pack（峰值从 19.5G 降到 ~16.5G）
  b) SpeculativeEngine 支持 `target_engine` 注入——spec 模式先构建+swap target（降到 2.5G）再加载 draft
- **PPL 评测的 cache 残留坑（第二次踩）**：engine 复用模型的 PPL 评测必须窗口级 reset cache（512 token 残留让 PPL 虚高 10 倍：16→162）。bench_ppl.ppl_of_model 已加 reset_fn 参数。
- 8B 模型显存账：fp16 16.4G（卡满）→ W4 2.49G + KV4@32K ~870MB + draft 1.2G ≈ **4.6G，24G 卡从"装不下 32K"到"富余 5 倍"**。
